# Artifact schema — `.plan.yaml` and `log.jsonl` event schemas

The plan artifact lives in `context/plans/<vision-slug>/`. The append-only `log.jsonl` is the
source of truth; the readable tree is generated from it by `generate-plan-surface.py`. Nothing
in the generated tree is hand-edited — a change is an append to the log, never an edit.

Schemas documented here match what Slice 1 built — every field and event type is exercised
by the fixture at `evidence/artifact-fixture/`.

---

## `.plan.yaml` — machine-readable state

Generated by `generate-plan-surface.py`. Read this to determine plan status without replaying.

```yaml
vision: "<title>"                  # string | null — from vision-set
current_wave: <wave-id> | null     # the open wave, or null
branches:
  <slug>:
    name: "<display name>"
    status: sketched | detailed    # transitions on branch-detailed
    goals:
      <goal-id>:
        title: "<goal title>"
        status: emitted | skipped | gate-1-passed | gate-2-passed
waves:
  - id: <wave-id>
    branch: <slug>
    status: open | closed
decisions: <count>
assumptions_open: <count>          # not yet falsified
questions_open: <count>            # not yet resolved
run_records: <count>
```

**Goal status** is derived from events, never set directly:

| Status | Set by |
|---|---|
| `emitted` | `goal-emitted` — initial |
| `skipped` | `goal-skipped` — will not proceed |
| `gate-1-passed` | `gate-passed` with `gate: gate-1` |
| `gate-2-passed` | `gate-passed` with `gate: gate-2` |

No `completed` status — completion is derived from disk by gate 1, not declared.

## `log.jsonl` — append-only source of truth

Each line: `{"event": "<type>", "timestamp": "<ISO>", "data": {...}}`. Exactly 15 event
types; unknown types cause the generator to exit with a fatal error.

---

## Event vocabulary — 15 events

### Plan-level events

**`vision-set`** — logged when the vision is written (Step 2).
Data: `title` (string), `summary` (string).

**`branch-sketched`** — logged once per branch (Step 2).
Data: `slug`, `name`, `summary`. The slug is the `.plan.yaml` key and directory name.

**`branch-detailed`** — logged when a branch is decomposed into goals (Step 3c).
Data: `slug`. Transitions status from `sketched` to `detailed`.

### Wave events

**`wave-opened`** — logged when a wave begins (Step 3b).
Data: `wave_id`, `branch`. Sets `current_wave`. Only one wave open at a time.

**`wave-closed`** — logged when a wave completes (Step 3e).
Data: `wave_id`. Clears `current_wave` if it matches.

### Goal events

**`goal-emitted`** — logged when a goal is produced with all five fields (Step 5).
Data: `branch`, `goal_id`, `title`, `wave`. The goal's full content lives in the branch
directory, not in the log event.

**`goal-skipped`** — logged when a goal will not proceed (Step 3e). Distinct from blocked:
blocked = *cannot proceed yet*; skipped = *will not proceed, downstream stops waiting*.
Data: `branch`, `goal_id`, `reason`. Maps to the bus's existing `cancelled` after dispatch.

### Decision and assumption events

**`decision-made`** — logged when a decision is recorded.
Data: `id`, `title`, `why`, `implications`. The `implications` field states consequences at
decision time — what makes a register usable months later.

Example:
```json
{"event":"decision-made","timestamp":"2026-07-20","data":{"id":"D1","title":"Use JSON Schema for validation","why":"Only format all providers support.","implications":"Locks validation to JSON Schema tooling."}}
```

**`assumption-recorded`** — logged when an assumption is identified.
Data: `id`, `text`, `provenance`, `confidence` (`low`/`medium`/`high`), `dependents` (list
of branch slugs or goal IDs). This structure drives wave ordering: highest dependents x
lowest confidence goes first.

**`assumption-falsified`** — logged when an assumption proves wrong.
Data: `id`, `reason`. The generator marks the assumption as falsified with date and reason.

### Question events

**`question-opened`** — logged when a question cannot be answered immediately.
Data: `id`, `text`, `resolves_when` (what evidence or decision would close it).

**`question-resolved`** — logged when a question is answered.
Data: `id`, `resolution`.

### Verification events

**`gate-passed`** — logged when a verification gate is cleared.
Data: `goal_id`, `gate` (`gate-1` mechanical · `gate-2` judged · `vision-approval` plan-level).
Gate 2 runs only after gate 1 passes. **`goal_id` is present for the goal gates and absent for
`vision-approval`**, which records the operator gate on the vision and branch map (Step 2) and
**changes no goal's status**.

**`verdict-recorded`** — logged when a gate-2 judge writes a verdict.
Data: `goal_id`, `result` (`pass`/`fail`), `detail`. The verdict is an artifact that gate 1
then checks for — a judge that sets status directly is declared status wearing a lab coat.

**`run-record-written`** — logged when a run record captures actuals for a completed goal.
Data: `id`, `goal_id`, `detail`. Captures what actually happened — which assumptions were
falsified, whether the goal completed without prescribed steps. After ten to twenty plans
these records provide data to revise the sizing numbers in Step 4.

## Generated files

`generate-plan-surface.py` produces five files from `log.jsonl`:

| File | Contents |
|---|---|
| `.plan.yaml` | Machine-readable state (schema above) |
| `INDEX.md` | Branch map, goal status, wave history, verification, run records |
| `decisions.md` | Register: ID, date, title, why, implications |
| `assumptions.md` | Register: ID, date, text, provenance, confidence, dependents, status |
| `questions.md` | Log: ID, date, text, resolves_when, status |

The regeneration-is-a-no-op guard (`check-plan-surface.sh`) verifies the generator produces
no diff against committed files.

## Directory structure

```
context/plans/<vision-slug>/
  .plan.yaml        # generated
  INDEX.md           # generated
  direction.md       # hand-written — the vision
  decisions.md       # generated
  assumptions.md     # generated
  questions.md       # generated
  log.jsonl          # append-only source of truth
  branches/NN-<slug>/   # goals live here when detailed
```
